# Decisions

Append-only log of architectural and process decisions, with the reasoning. Newest entries go at the bottom. Do not rewrite history; add a new entry that supersedes an old one if needed.

## 2026-10-09

- **Git push authentication works through Windows Git Credential Manager.** WSL git uses the helper script `~/.local/bin/git-credential-manager.sh` (set as `git config --global credential.helper`), which delegates to `/mnt/c/Program Files/Git/mingw64/bin/git-credential-manager.exe`. It reuses the GitHub credentials already stored by Windows, so pushes are non-interactive. A space-free wrapper is required because git splits credential.helper on whitespace. The git identity (`dpuro99@users.noreply.github.com`) lives in the repo-local `.git/config`, and this file is not committed.
- **WSL cannot write `git config` on the OneDrive mount.** `git config user.name`/`email` fails with `chmod ... Operation not permitted` on `.git/config.lock`. Workaround: edit `.git/config` directly. Global config (`~/.gitconfig`) is on the Linux filesystem and writes fine.

- **Line endings normalized to LF in the repository.** Added `.gitattributes` (`* text=auto` plus explicit `eol=lf` for source and `binary` for images/PDFs) and ran `git add --renormalize`. The working tree had accumulated CRLF from Windows editors, which turned small edits into whole-file diffs and would have polluted `git blame`. Rationale: keep reviewable diffs and a consistent repository.

- **Memory bank is the cross-session memory mechanism.** opencode has no persistent memory between sessions, so `memory_bank/` (`projectBrief.md`, `systemArchitecture.md`, `progress.md`, `decisions.md`) is the durable project context. `memory_bank/projectBrief.md`, `systemArchitecture.md`, and `decisions.md` are auto-loaded every session via the `instructions` field in the root `opencode.json`; `progress.md` is read on demand because it changes often.

- **`/commit-push` custom command.** Added `.opencode/command/commit-push.md` so a single command reviews changes, updates `memory_bank/progress.md`, runs `npm test`/`lint`/`build`, commits, and pushes. Rationale: make the memory-update step part of the standard workflow instead of relying on recall.

- **Navigation stays router-free.** `src/App.jsx` owns theme, auth/session, landing-vs-dashboard gating, selected event, and active module through local state. Do not add a router or state library without a demonstrated need and approval.

- **Supabase is authentication only.** Google OAuth via `src/supabaseClient.js`; practice tools persist explicitly to browser `localStorage`. When backend practice storage is added, it must be scoped by authenticated user id and event id and guarded by Row Level Security, not client-side filters.

- **Domain scope.** Focus on Regional/Invitational material unless asked otherwise. Prefer student-authored data tools over hardcoded quiz/answer banks. Never invent Science Olympiad rules or scoring formulas; cite the manual page/section beside rule-specific summaries and calculators.

## 2026-10-10

- **Event tool components are lazy-loaded.** `registry.js` wraps each event tool in `React.lazy(() => import(...))` (see the `ti-*` module `component` shape); `App.jsx` renders them inside a single `<Suspense>` fallback. Rationale: shrink the initial bundle (634 kB → 561 kB) and ship only the tool a user opens. `EventRulesOverview` stays an eager import so event overviews remain part of the main chunk. New event tools should keep the same lazy pattern; do not add eager top-level `import` of tool components to `registry.js`.

## 2026-10-10 (second pass)

- **Commit policy is ask-first.** Never commit, amend, push, or open a PR unless the user explicitly asks; only an explicit "commit and push" or the `/commit-push` command is a standing go-ahead. Rationale: the agent committed several batches without asking, and the user wants a review gate. Enforced in the global `AGENTS.md`.
- **Build-event-tool skill redesigned around a canonical tool spec block.** Every event's `tool-ideas.md` now uses one `## Tool:` block per tool with fixed fields (Status/Goal/Core interaction loop/Content & data/UI components/Scoring & feedback/Level gating/Persistence/Open questions). The skill is format-agnostic (extracts the contract, never re-invents it) and enforces a logic-first build: co-located `*.js` module + `node:test` unit test in `tests/` before JSX, lazy registration in `registry.js`, reference components instead of design questions, and a mandatory `npm test`/`lint`/`build` gate. Rationale: the old skill expected a prose layout the specs didn't follow, so builds were slow and under-verified.
- **Canonicalized the nine `tool-ideas.md` plans.** All events (anatomy, boomilever, chemlab, circuitlab, designergenes, dynamicplanet, electricvehicle, rocksandminerals, writeitdoit) converted to the spec block template without changing any verified rule content or Live/Planned status; tests only regex registry/JSX sources, so spec md is safe to edit.
- **Silenced the Vite chunk-size advisory.** `build.chunkSizeWarningLimit: 600` in `vite.config.js`. Rationale: after lazy-loading, the 561 kB main chunk is framework+Supabase only (164 kB gzip) — a real threshold raise, not hiding an unbounded problem; per-tool chunks stay small.
- **Global vs project instruction split.** Generic, project-agnostic rules (git hygiene and ask-first committing, cross-session memory habits, a11y/security, working style) moved to `~/.config/opencode/AGENTS.md`; the repo `AGENTS.md` is now repo-specific only (commands, architecture contracts, event conventions, domain rules). Rationale: avoid duplicating generic practice in every project's AGENTS.md.

## 2026-10-11 (rules-compliance audit)

- **Verify every rule claim against the actual manual text.** Extracted both 2027 manuals to text (pdf-parse via a throwaway npm package outside the repo) and cross-checked every event's registry entry, overview copy, `info.md`, and live tool. Result: live logic was already exact (EV formula reproduces the manual's example runs), but several planning specs carried fabricated details (page ranges, a clipboard rule, a "rotator" WIDI year, a faux "metamorphic focus") inherited from earlier drafts. From now on, `tool-ideas.md`/`info.md` may only state facts verifiable in the manual text or confirmed FAQ; treat PDF page numbers as approximate.
- **Dynamic Planet citations are clause-accurate.** Water budget → §3.a.ii; discharge/velocity/load → §3.f.ii–iii; lake water budgets → §3.h.ii (pp. C24–C25). The previous single broad "§3.f" cite was incomplete; tests updated to match.
- **Circuit Lab practice calculator computes series AND parallel equivalent resistance.** `calculateSeriesParallel` existed in `circuitUtils.js` but was never used; the UI only summed resistances while claiming "series/parallel." Wired the function in so both results are shown; the tool-ideas spec now matches the shipped feature set (Ohm's law + series/parallel R_eq), and a future "Safe Hands-on Task Simulator" is marked Planned.
- **EV clarification kept but grounded.** The official FAQ page (`soinc.org/faq/electric-vehicle-div-c`) is live and contains the program-development question, so the clarification stays; a fabricated long-slug permalink was removed. Registry EV modules now carry `manualReference` like every sibling event.

## 2026-10-11 (tool-plan audit)

- **Tool-plan audit applied to all nine `tool-ideas.md` files.** Reviewed each planned tool for prep value; the live calculators/logs were judged strong and left unchanged. Two systemic issues drove the edits: (1) several planned "practice" tools were hardcoded question/answer banks in disguise (Anatomy Station Practice, Designer Genes Molecular Biology Practice, Dynamic Planet Map/Data Stations), which conflicts with the student-authored-tool preference and duplicates existing practice-test platforms; and (2) no event had an active-recall/flashcard tool despite recall being the bottleneck in the content events.
- **Planned answer-banks reshaped into generators/simulators or student-authored tools.** This removes the recurring "content architecture needed" blocker and the dependency on externally sourced datasets: Anatomy Self-Quiz Flashcards (student-authored), generated spirometry/flow-volume practice, process simulator, diagram drill; Designer Genes Molecular Sequence Workbench; Dynamic Planet calculator toolbox and generated map/hydrograph cases; Rocks and Minerals Mineral Identification Key + user-authored specimen cards; Circuit Lab digital-logic workbench and PN-junction/LED calculator.
- **Cross-event archetypes are now reusable by design.** The specs deliberately repeat: a quantitative generator (gas laws, circuits, EV score, freshwater, stoichiometry, sequence, ID key), a student-authored flashcard/SRS tool, a build/test log (EV → Boomilever), a timer (WIDI phases, Boomilever 6 min, EV 8 min), a compliance checklist (EV, Boomilever → Circuit, Chem Lab), and an interactive process/diagram simulator. Building one should reuse the pattern for the others rather than redesigning it.
- **No rules content changed.** All new/changed entries are tool-design changes; every manual citation, level gate, and Live/Planned status was preserved. All additions are `Planned`, so `registry.js`, components, and tests are unaffected.

## 2026-10-11 (tool taxonomy: specialized tools, reference compiler, general backburner)

- **Saturated niches confirmed; do not compete there.** Web research this session found the question-bank/practice-test space already owned by scio.ly, olyprep, "Grind," examzify, and sciolyprep; flashcards by Quizlet/Anki/Grind; team results analytics by SciOly Analyzer and SciolyAnalysis; and competition-day scheduling by the ATX app. The product's moat is event-specialized tools plus the reference compiler, not generic prep content. Sampled existing per-event tool sites (scioly.tools for Codebusters, SciOlyID for specimen ID) also confirm the per-event tool model is the right one.
- **Reference & Study Compiler is the flagship organizer family and one combined tool per event.** It pairs a study tracker whose objective outline is transcribed from the manual's official topic list (rule-derived, not invented, and already summarized in each `info.md`) with an allowed-resource compiler; mastery status drives pruning of the printed sheet. One shared engine with per-event config: **sheet mode** for Anatomy (one double-sided 8.5×11 sheet, per team), Designer Genes (same), and Chemistry Lab (per participant); **binder mode** for Circuit Lab, Dynamic Planet, and Rocks and Minerals (including pinned external items and the no-removal-during-stations constraint for DP/R&M). Sheet mode ships before binder mode because it is materially smaller. The maintenance cost of transcribing objectives per event is accepted in exchange for concrete guidance.
- **Generators are in; stored banks are out.** Generated practice (gas laws, circuits, stoichiometry, molecular sequences, mineral key, hydrographs) is allowed because it computes novel problems with shown work rather than serving a scraped question bank.
- **General (non-event-specific) tools are backburnered: max 1–3.** Tracked in `src/components/general/tool-ideas.md` with an inert `generalToolIdeas.js` TODO placeholder (not registered in `registry.js`, not app-wired): generic event timer, self-quiz flashcards (student-authored content only), rules-change highlighter. Flashcard content the student authors is the only defensible version; a bundled deck would just be scio.ly-lite.
- **Official SO guidance validates the reference compiler.** The SO Student Companion and preparation-tips pages are almost entirely about building and pruning cheat sheets/binders (add early, drop mastered material, include diagrams, print/laminate, back up) — a workflow no existing platform tools.
