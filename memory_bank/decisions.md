# Decisions

Append-only log of architectural and process decisions, with the reasoning. Newest entries go at the bottom. Do not rewrite history; add a new entry that supersedes an old one if needed.

## 2026-10-09

- **Git push authentication works through Windows Git Credential Manager.** WSL git uses the helper script `~/.local/bin/git-credential-manager.sh` (set as `git config --global credential.helper`), which delegates to `/mnt/c/Program Files/Git/mingw64/bin/git-credential-manager.exe`. It reuses the GitHub credentials already stored by Windows, so pushes are non-interactive. A space-free wrapper is required because git splits credential.helper on whitespace. The git identity (`dpuro99@users.noreply.github.com`) lives in the repo-local `.git/config`, and this file is not committed.
- **WSL cannot write `git config` on the OneDrive mount.** `git config user.name`/`email` fails with `chmod ... Operation not permitted` on `.git/config.lock`. Workaround: edit `.git/config` directly. Global config (`~/.gitconfig`) is on the Linux filesystem and writes fine.

- **Line endings normalized to LF in the repository.** Added `.gitattributes` (`* text=auto` plus explicit `eol=lf` for source and `binary` for images/PDFs) and ran `git add --renormalize`. The working tree had accumulated CRLF from Windows editors, which turned small edits into whole-file diffs and would have polluted `git blame`. Rationale: keep reviewable diffs and a consistent repository.

- **Memory bank is the cross-session memory mechanism.** opencode has no persistent memory between sessions, so `memory_bank/` (`projectBrief.md`, `systemArchitecture.md`, `progress.md`, `decisions.md`) is the durable project context. `memory_bank/projectBrief.md`, `systemArchitecture.md`, and `decisions.md` are auto-loaded every session via the `instructions` field in the root `opencode.json`; `progress.md` is read on demand because it changes often.

- **`/commit-push` custom command.** Added `.opencode/command/commit-push.md` so a single command reviews changes, updates `memory_bank/progress.md`, runs `npm test`/`lint`/`build`, commits, and pushes. Rationale: make the memory-update step part of the standard workflow instead of relying on recall.

- **Navigation stays router-free.** `src/App.jsx` owns theme, auth/session, landing-vs-dashboard gating, selected event, and active module through local state. Do not add a router or state library without a demonstrated need and approval.

- **Supabase is authentication only.** Google OAuth via `src/supabaseClient.js`; practice tools persist explicitly to browser `localStorage`. When backend practice storage is added, it must be scoped by authenticated user id and event id and guarded by Row Level Security, not client-side filters.

- **Domain scope.** Focus on Regional/Invitational material unless asked otherwise. Prefer student-authored data tools over hardcoded quiz/answer banks. Never invent Science Olympiad rules or scoring formulas; cite the manual page/section beside rule-specific summaries and calculators.

## 2026-10-11 В (browser-audit harness + global /audit command)

- **The audit capability is a global opencode command, not a project file.** `/audit` lives at `~/.config/opencode/command/audit.md` with `agent: build`; it drives the *project's* Playwright harness when one exists and falls back to a full sweep otherwise. Rationale: the user wants to audit any project, and the harness (which must know the app) is rightfully repo-owned. `full`/`all` argument forces a full sweep.
- **First run audits everything; later runs audit only what changed since the last successful audit.** Baseline = the last audited git commit, stored per-repo at `$HOME/.config/opencode/audit/<repo-slug>.baseline` (slug = toplevel basename, sanitized). The changed set is `git status --porcelain` ∪ `git diff --name-only <baseline> HEAD`; `tests/e2e/incremental.mjs` maps those paths to specs and stamps the baseline only on a green run. Rationale: keep repeat audits fast and cheap.
- **Scope mapping errs toward full coverage.** `src/components/events/<event>/**` → core + that event's spec; anything shared/general/unknown, app/config files, or `tests/e2e/**` → all specs. Rationale: a wrong narrow scope would miss regressions, so unknown = full.
- **Baseline location must match between the agent shell and the Node runner.** Under WSL-interop, Windows-node's `homedir()` (`C:\Users\…`) differs from the agent shell's `$HOME` (`/home/david`). The runner prefers `OPENCODE_AUDIT_DIR`, then a POSIX `process.env.HOME`, then `homedir()`, and `/audit` exports `OPENCODE_AUDIT_DIR="$HOME/.config/opencode/audit"`. Two Windows-specific fixes were required: spawn the Playwright CLI via `process.execPath` + `node_modules/@playwright/test/cli.js` (bare `npm` is not spawnable without a shell), pass test paths repo-relative with forward slashes (Playwright does not match absolute `C:\…` filters), and normalize `git rev-parse --show-toplevel` (forward slashes) before comparing to `repoRoot` (backslashes).
- **Baseline is repo-local, not home-based (supersedes the location above).** WSL→Windows interop neither forwards custom env vars nor preserves the POSIX `$HOME` (Windows node saw `HOME=C:\Users\david`), so `OPENCODE_AUDIT_DIR` never reached the runner and it stamped an unusable Windows-home path that diverged from the agent shell. The baseline now lives in the gitignored `.opencode-audit.baseline` at the repo root, which both the agent shell and the browser runner reach through the same mounted working directory. The global `/audit` command falls back to the home-based path only for projects without a harness.
- **Guest mode only, records evidence.** Specs seed `sessionStorage['olympiad-studio-navigation']` to enter the dashboard as a guest (no OAuth) and capture a full-page screenshot + DOM text snapshot per screen into `test-results/screenshots/`. First full sweep: 44/44 pass; findings (no functional defects; low-severity duplicate headings, EV run-logger native-validation shadowing) are recorded in `AUDIT.md`. `test-results/` and `playwright-report/` are gitignored; `AUDIT.md` is committed as the report.
- **"Not verifiable headlessly" was too weak — emulate the media instead.** The first sweep listed `window.print()` as unverifiable and moved on, which let a real HIGH bug (blank printed page, caused by `#root { display: none }` in print CSS hiding the nested `.reference-print-area`) slip through. Lesson: when output depends on a media/environment context, drive that context (`page.emulateMedia({ media: 'print' })`, `page.pdf()`, forced colors) and assert visibility, rather than declaring it out of scope. The harness now has `expectPrintSheetRenders()` in the shared compiler flow.

## 2026-10-11 (harness hardening: drive the medium, all observable states)

- **Every observable state must be reproduced and asserted, not deferred.** Hardening pass applied the print lesson across the whole harness: responsive (`setViewportSize`/`browser.newContext` at 375 px + the 720 px breakpoint), theme (assert computed `body` background differs light vs dark, not just the `data-theme` attribute), a11y (unique accessible heading names), and resilience (disabled `localStorage`, corrupt `localStorage` per tool, corrupt `sessionStorage` nav, cancelling destructive dialogs, JSON import/rehydrate). The global `/audit` command was updated with an explicit "never declare an observable state unverifiable — drive the medium instead" section, and `AUDIT.md`'s limitations list now only contains genuinely external items (OAuth, real Supabase network, cross-browser) plus OS-level print pagination. Rationale: the blank-print bug proved that "headless can't verify it" is a coverage hole, not a limitation.
- **The pass found two real defects, both fixed at the source.** (1) **MEDIUM:** every module's 375 px test failed on ~11 px horizontal overflow — `.dashboard-sidebar .dashboard-brand-button` kept `width:100%` while `flex-shrink:0` in the ≤720 px horizontal-row sidebar, consuming the full viewport and shoving the tool `<nav>` off-screen; fixed with `width:auto` in the mobile media query. (2) **LOW:** in-tool `<h2>` titles duplicated the page `<h1>` module label (screen-reader heading ambiguity) — removed the redundant titles and promoted section headings `h3`→`h2`. Added `expectNoHorizontalOverflow` and `expectUniqueHeadingNames` guards so both regressions now fail the suite.
- **`page.pdf()` text extraction is the print regression guard.** `captureSheetPdf` renders the page as a real PDF and asserts the extracted text contains the authored block; `pdf-parse` is lazy-imported (`await import('pdf-parse')`) because a top-level import pulled pdfjs-dist and added ~10 s to every test. `expectPrintSheetRenders` (emulated print media) still runs everywhere; the PDF check runs only where a `pdfText` is supplied (anatomy, circuitlab).
- **Suite size is intentional; keep per-tool specs shallow and put cross-cutting invariants in `core.spec.js`.** All 23 modules get render + 375 px coverage from the app-map loop; event specs drive deeper interactive flows; `resilience.spec.js` covers storage/theme/dialog/import. E2E grew 44 → 79 tests (runs ~10 min single-worker). Do not duplicate the app-map loop per event.

## 2026-10-14 (Circuit Lab digital logic workbench)

- **Shipped v1 is a truth-table workbench, not a wiring canvas.** The Digital Logic & Boolean workbench (`circuitlab/DigitalLogicWorkbench.jsx` + `circuitlab/booleanLogic.js`) covers gate truth tables, expression → truth table with canonical sum-of-products, expression equivalence (De Morgan's Law), and guided combinational circuits (half adder, full adder, 2:1 multiplexer). A drag-and-drop gate canvas and a Karnaugh-map minimizer were deliberately left out of v1 to avoid a large, hard-to-verify surface; the pure `booleanLogic.js` module (parse → AST → evaluate → truth table) is the testable core with 9 `node:test` cases.
- **Expressions support variables A–D with AND/OR/NOT/XOR.** The tokenizer also accepts the symbolic forms `·`/`+`/`'`/`!`/`^` and the C-style `&&`/`||`, plus implicit NOT and parentheses. Variables are single letters (A is MSB) and the evaluator caps at 4 variables; multi-letter tokens (e.g. `Cin`) are rejected, so the full adder uses `C` as its carry-in. Errors are returned as `{ error }` values (clear messages) rather than thrown.
- **Scope is grounded in the 2027 Division C manual.** Gate/Boolean/combinational content is §3.c.viii (+ §3.e.iv; §3.e.iii binary representation and addition underpin the adders). Clock/timing/flip-flop content (§3.c.ix) is State/National-only and excluded, which the tool states explicitly. Everything is generated from user input — no preset question bank.
- **Module identity and registration follow the established contract.** `id: 'digital-logic'`, `ti: 'ti-binary'`, lazy import in `registry.js`, `additionalModules` entry with `manualReference: 'Division C Rules Manual, pp. C16–C17'`, added to `tests/e2e/app-map.json` (25 modules now get shared render + 375 px coverage). The tool reuses the shared UI primitives (`ToolHeader` without a `title`, `Card`, `SelectField`, `TextField`, `Button`, `StatusMessage`/`ResultPanel`, `SectionHeading`) and keeps its truth-table grid as a local presentational component. `<caption>` is used for table context but is queried in e2e via a `caption` locator, since Playwright does not expose it through `getByRole('caption')`.

## 2026-10-14 (digital logic workbench: minimization, builder, drill)

- **The workbench grew four more modes, all pure-logic-backed.** Added to `booleanLogic.js`: `kmapMinimize` (Quine–McCluskey + a minimum-cover search), `kmapLayout` (gray-code grid), `multiOutputTruthTable`, `generateDrill`/`checkDrillAnswer`/`parseMintermInput`, and `simulateCircuit` (gate netlist). UI panels `KMapMinimizer.jsx`, `MultiOutputTruthTable.jsx`, `CircuitBuilder.jsx`, `LogicDrill.jsx` join the workbench as tabs; `TruthTable.jsx` was extracted so all panels share one table. The workbench stays a single registry module (`digital-logic`) — the new modes are tabs, not separate events.
- **Minimization is exact, not a heuristic, for ≤4 variables.** `chooseMinimumCover` enumerates prime-implicant subsets (bitmask) to find the minimum-cardinality cover, breaking ties by fewer literals, so the returned sum-of-products is genuinely minimal. Term display order is deterministic (fewest literals first, then alphabetical) so output is stable. Implicants carry a precomputed `label` for the UI.
- **The circuit builder is a connection-based netlist, not a spatial drag-and-drop canvas.** Each gate references a circuit input or an earlier gate via dropdowns; `simulateCircuit` validates references (no forward references / unknown nodes) and evaluates the netlist over every input combination. Rationale: dropdowns keep the builder keyboard-accessible and exactly testable headlessly, whereas a spatial canvas is a large, flaky surface. A drag-and-drop canvas remains an explicit open question.
- **The practice drill generates its own problems and grades them in logic.** `generateDrill(random)` builds a random truth table (2–3 variables), derives the minimal form, and emits either a "list the minterms" question or a 4-option "pick the minimal sum-of-products" question with generated, non-equivalent distractors; `checkDrillAnswer` grades both. `random` is injectable, so the unit test drives it with a seeded LCG and asserts the options/answer are self-consistent over 40 iterations.
- **New tests: `tests/circuitlab-workbench.test.js`** covers minimization (incl. all-0/all-1 and XNOR), K-map layout covering every minterm once, multi-output columns and error labelling, seeded drill self-consistency/grading, and circuit simulation (evaluation, forward-reference and unknown-node rejection). Suite: 79 unit + 89 e2e; lazy chunk 30.5 kB (gzip 9.5 kB), lint/build clean.

## 2026-10-14 (digital logic workbench: drag circuit canvas)

- **The netlist builder was replaced by a spatial drag-and-drop circuit canvas** (`circuitlab/CircuitCanvas.jsx`); `CircuitBuilder.jsx` and the netlist-only `simulateCircuit` were removed as dead code. The screen now compiles a schematic graph instead of an ordered netlist: `compileSchematic` validates node/wire references (unknown nodes, OUTPUT-as-source, input-as-target, wrong port, double-connected input), derives a topological order via Kahn's algorithm and reports feedback loops, and `evaluateSchematic`/`schematicTruthTable` simulate it. Suite: 80 unit + 89 e2e; lazy chunk 36.3 kB (gzip 11.5 kB), lint/build clean.

## 2026-10-14 (digital logic canvas: wire deletion, auto-layout, persistence)

- **The canvas persists to `localStorage` under `olympiad-studio.circuitlab-c.2027-logic-canvas`.** `{ nodes, wires, assignment }` is restored in a lazy `useState` initializer (via `loadSavedCircuit`, which shape-validates and returns a `corrupted` flag) and written back in an effect on every change. Unlike the explicit save/restore siblings, a canvas auto-persists because a save button would interrupt the drawing flow. A corrupt/unavailable read starts from a fresh circuit and shows a `role="alert"` (`StatusMessage tone="error"`), matching the resilience convention. The effect's write-failure `setStorageError` is deferred through `window.setTimeout` to satisfy `react-hooks/set-state-in-effect` (the same pattern the sibling tools use); the read-error alert is what the resilience tests assert. Gate ids are now derived from existing node ids (`G<n>` scan) rather than a counter, so restored circuits can't collide with newly added gates.
- **Wires are removable by clicking them.** Each wire is a `<g>` pairing a transparent wide hit path (`.circuit-wire-hit`, `pointer-events: stroke`, `role="button"`, `tabIndex=0`, `aria-label="Delete wire from X to Y"`) with the visible value-coloured path (`.circuit-wire-visible`, `pointer-events: none`). The hit path handles both click and Enter/Space, so wire deletion is keyboard-accessible; group `:hover` adds a drop-shadow in CSS (not JS). A straight horizontal wire has a zero-height bounding box, so e2e asserts attachment (`toHaveCount(1)`) rather than visibility.
- **`layoutSchematic` is a pure, tested auto-layout.** Added to `booleanLogic.js`: it compiles the circuit, computes each node's depth (inputs 0, gates/OUTPUT ≥ 1 via the longest source path over the topological order), and assigns non-overlapping columns (`LAYOUT.columnGap`/`rowGap`, left-to-right by depth, stacked by current `y` with id as the tiebreak). The `Tidy up` button applies it and is disabled while the circuit has a compile error. Unit tests cover input/gate/output column ordering, finite positions, and the feedback-loop error path.

## 2026-10-15 (interactivity-first convention)

- **Interactive is the Studio's default tool idiom, codified as a strong default with justifiable exceptions.** `AGENTS.md` gains an `## Interactivity` section: live derivation during render (no Calculate button for values already in state), direct manipulation for spatial/graphical domains, keyboard+accessible-name requirements, `localStorage` persistence, and a two-question checkpoint before building/keeping a non-interactive tool — (a) would a live/interactive version make sense? ## 2026-10-15 (interactivity retrofit: live calculators + storage on slug)

- **The remaining Calculate gates were removed; four tools now derive during render.** Circuit Lab practice, Chemistry gas laws (solver + Dalton + Graham), Chemistry kinetics (per-trial rates + a quantity-vs-time line chart), and Dynamic Planet freshwater (discharge + water budget + a channel cross-section and budget bars) were converted from "submit → result" to live derivation.
