# Write It...Do It B — Event Breakdown

## Overview
- **Team size:** Exactly 2 participants (fixed roles — one writer, one builder)
- **Duration:** ~50 minutes total (25 minutes writing + 20 minutes building, plus supervisor transition time)
- **Format:** Two-phase communication/construction event — Partner A writes a build description from observing an object; Partner B builds the object from only that written description
- **No calculator, no lab equipment, no reference materials of any kind**

## Event Parameters
- The participant who will do the **writing** must bring a writing utensil.
- **No other materials or resources are allowed** for either participant — this is one of the most resource-restricted events in Science Olympiad.

## What the "Object" Is
- The object may be **abstract** (not representing anything recognizable) but is **identical for every team** at that competition.
- It's built from things like: basic science/craft materials, inexpensive materials (straws, push pins, Styrofoam balls, paper cups, popsicle sticks, etc.), or commercial construction sets (K'nex, Tinker Toys, Lego, Lincoln Logs, etc.).
- Event Supervisors intentionally try to use **different materials each year** than the previous year, so teams can't rely on prior-year materials familiarity.

## What Actually Happens on Competition Day

### Phase 1: Writing (25 minutes)
1. **Only one team member** (the "writer" / "describer") is shown the pre-built object.
2. This participant is **not allowed to touch the object** unless the Event Supervisor specifically permits it — observation is primarily visual.
3. The writer has **25 minutes** to write a description of the object and step-by-step instructions for how to build it. **There is no advantage to finishing early** — you can't submit early for extra credit or move to the next phase faster.
4. **Strict format restrictions on the description:**
   - **No drawings or diagrams** of the model or any subsection of it — this is the single most important constraint of the entire event.
   - Numerals, words, and single letters are allowed **as long as they fit within the context of normal written description** (i.e., you can write "attach piece 3 to the left side," but you can't draw a picture with labeled parts).
   - Abbreviations are allowed and **do not need to be defined/spelled out**.
   - Editing marks, punctuation, and scientific symbols are allowed if they fit within the written description context.
5. At the end of 25 minutes, the Event Supervisor collects the written description and **physically hands it off** to the second team member — the writer has no further involvement.

### Phase 2: Building (20 minutes)
1. The second team member (the "builder") receives **only the written description** — no verbal clarification, no access to the original object, no drawings.
2. The builder has **20 minutes** to construct/recreate the object using the same set of building materials, based purely on interpreting the written instructions.
3. The builder works entirely from text — if the description was ambiguous, incomplete, or hard to follow, that's now the builder's problem to solve through interpretation, not something they can ask about.

## Scoring
- **The team whose built object is closest to the original wins** — but only if their written description also complied with the no-drawings rule.
- **Scoring is piece-by-piece**, not holistic: each individual piece of the object earns points for being correct on multiple independent dimensions:
  - Proper **size**
  - Proper **color**
  - Proper **location** (where it is in the overall structure)
  - Proper **orientation** (which way it's facing/rotated)
  - Proper **connection** (correctly attached to the right other piece(s))
- **Cascading connection credit:** if a piece is connected correctly to something that was itself placed incorrectly, the correct *connection* still counts toward score — errors don't necessarily zero out everything built on top of them.
- **No penalty for unused pieces** — if the builder has leftover material they didn't use, that alone doesn't cost points (though presumably the missing pieces that should have been used will cost points via the piece-scoring above).
- **Drawing a subsection of the model** during the writing phase results in the team being dropped to **Tier 2** (a worse-but-not-disqualified category).
- **Drawing an actual picture of the whole model** during the writing phase results in **full disqualification**.
- **Tiebreaker:** the time taken during the construction (building) phase — presumably faster correct builds break ties, though the rules text doesn't specify whether faster or slower is favored (logically, likely fastest correct completion, consistent with most build-event tiebreak conventions).

## Key Competitive Realities
- **This is fundamentally a technical writing and spatial communication skill event, not a science content event** — success depends entirely on the writer's ability to translate a 3D spatial structure into unambiguous, sequential, drawing-free text, and the builder's ability to parse and execute that text accurately. There's no "topic" to study in the traditional Science Olympiad sense.
- **The no-drawings rule is a hard constraint that shapes the entire writing strategy** — writers must develop a *systematic verbal vocabulary* for describing shape, position, orientation, and connection (e.g., consistent naming conventions for pieces, consistent spatial reference language like "left," "top," "second from the base") since they cannot fall back on even a simple sketch.
- **The event rewards a specific, learnable writing structure**, likely including things like: describing pieces before describing assembly steps, using a consistent piece-naming/numbering system introduced early in the description, sequencing instructions in an order that mirrors physical buildability (i.e., not referencing a piece before it's been introduced), and calling out orientation/color explicitly for every piece since those are separately scored dimensions.
- **The builder's role requires literal, careful instruction-following under time pressure** — 20 minutes to fully parse and execute someone else's written instructions (with no ability to ask questions) rewards a builder who reads the entire description first to build a mental model before starting, rather than building step-by-step on a first read and getting stuck on later ambiguous steps.
- **Partner role-fit matters** — since the roles are fixed and distinct (one person only writes, one person only builds, per team of exactly 2), practicing both roles individually — and specifically practicing the *handoff* (i.e., a real writer's actual output being handed to a real builder who has never seen the object) — is the only way to genuinely test whether a given written style actually works, since the writer never gets feedback on ambiguity in real time.
- **Because the object and materials change every year**, this event cannot be "solved" by memorizing a specific solution — the transferable skill is the *process* of describing an unfamiliar object systematically, not familiarity with any specific object or material set. Practice should rotate through many different novel objects/material sets rather than mastering one.
- **Scoring rewards partial credit heavily** (piece-by-piece, multi-dimensional per piece) — meaning a team doesn't need a perfect build to score well; getting most pieces mostly right (correct connections especially, since those cascade) is likely to outperform an all-or-nothing mental model of the event.
